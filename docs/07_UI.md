## Визуальное направление

Выбран стиль: мягкий, дружелюбный космический интерфейс с серьёзной инженерной структурой.

- тёмный северный космос;
- сияние и холодные синие поверхности;
- стеклянные карточки;
- бирюзовые доступные связи;
- фиолетовые выбранные маршруты;
- коралловые отказы;
- аккуратный мультяшный спутник-маскот;
- высокая плотность данных без ощущения «админки».

Маскот используется в onboarding, empty, loading и success states. Он не должен отвлекать в режиме расследования аварии.

## Design tokens

```text
Background:       #071431
Surface:          #111E45
Surface elevated: #172653
Border:           #29437D
Primary violet:   #7C5CFF
Link cyan:        #53E6D0
Orbit blue:       #3B82F6
Warning:          #FFB284
Danger:           #FF5C7C
Text primary:     #F5F7FF
Text secondary:   #B6C1E6
```

- шрифт: Manrope или Inter;
- радиусы карточек: 16–24 px;
- минимальный размер клика: 40 px;
- анимации: 150–250 мс;
- табличные числа используют tabular numerals;
- статус нельзя кодировать только цветом: добавляются иконка, подпись и tooltip.

## Информационная архитектура

Основная навигация:

```text
Проекты | Сеть | Отказы | Исследования | Сравнение
```

Дополнительно: экспорт, настройки, тема, справка.

## Экран 1. Проекты и загрузка

Показывает:

- новый проект;
- загрузку JSON drag-and-drop;
- четыре примерных сценария;
- недавние проекты;
- статус последнего запуска.

После загрузки:

- валидный файл открывает обзор параметров;
- ошибочный файл показывает modal со списком ошибок, JSON path и действиями «выбрать другой»/«исправить и повторить».

## Экран 2. Сеть

### Левая панель

- выбор Variant;
- launch stage;
- RAAN и phase каждой плоскости;
- ISL range;
- кнопки «Preview» и «Рассчитать сутки»;
- индикатор несохранённых изменений.

### Центральная область

- Земля с фокусом на северные широты;
- активные и отказавшие спутники;
- орбитальные плоскости;
- текущие контакты;
- три клиента и шлюз;
- выбранный маршрут;
- резервный маршрут по отдельному toggle.

### Правая панель

- карточки C65/C70/C72;
- доступность за сутки;
- статус в выбранный момент;
- path и hop count;
- причина разрыва;
- время жизни маршрута при включённой стратегии Stable Route.

### Нижняя шкала

- отдельный трек для каждого клиента;
- зелёный — путь есть;
- тёмный/красный — пути нет;
- дополнительные оттенки причин;
- markers отказов;
- click переводит модель на тик;
- Play проигрывает сутки в ускорении.

## Экран 3. Отказы / Outage Detective

- выбор спутника на карте или в списке;
- начало и конец отказа;
- применение к draft-варианту;
- сравнение before/after;
- основной и перестроенный маршруты;
- список затронутых клиентов;
- причина каждого нового разрыва;
- блок критических аппаратов;
- кнопка «открыть первый затронутый момент».

Главный wow-момент: пользователь кликает на красный сегмент и видит две изолированные компоненты сети, а не просто сообщение «маршрут отсутствует».

## Экран 4. Исследования / Design Space Explorer

- выбор параметров X и Y;
- диапазон и шаг;
- budget эксперимента;
- прогресс sweep;
- heatmap доступности худшего клиента;
- contour 90%;
- Pareto plot «доступность vs максимальный перерыв»;
- таблица лучших вариантов;
- клик по точке открывает её конфигурацию;
- кнопка «сохранить как Variant».

Не называть корреляцию причинностью. Использовать формулировку «наблюдаемая зависимость на рассчитанных точках».

## Экран 5. Сравнение

- две или более карточки вариантов;
- изменённые параметры;
- KPI каждого клиента;
- delta в процентных пунктах и минутах;
- временные шкалы рядом;
- графики доступности;
- heatmap при наличии эксперимента;
- доказательная рекомендация;
- кнопки «применить», «клонировать», «экспортировать Evidence Pack».

## Системные состояния

Обязательны:

- empty project;
- drag over;
- validating;
- validation failed;
- run queued;
- running with stage/progress;
- calculation failed;
- success;
- stale result после изменения draft;
- no route;
- deleted/expired trace с возможностью пересчитать;
- offline/degraded infrastructure.

## Reference screens в репозитории

Мокапы лежат в корне репозитория; задают композицию, не данные:

- `Проекты(Расчёт).png` — проекты и загрузка сценария.
- `Ошибка.png` — ошибки валидации с JSON path.
- `Сеть.png` — основной экран сети: конфигурация, карта, карточка клиента, таймлайн.
- `Результат_расчета.png` — итог расчёта, сохранение варианта, экспорт.
- `Отказы.png` — отказ спутника, before/after, критические аппараты, причины на таймлайне.
- `Сравнение.png` — сравнение двух вариантов с рекомендацией.

В код нельзя переносить текст и числа с mockup как источник данных. Mockup задаёт композицию; всё содержимое приходит из API.

## Responsive scope

- основной target: desktop 1366–1920 px;
- минимум: usable tablet landscape;
- полноценный mobile не является приоритетом кейса;
- при узком экране боковые панели превращаются в drawers.
