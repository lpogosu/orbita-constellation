Ты работаешь над продуктом «ОРБИТА»: backend-first веб-платформой для расчёта временного
графа спутниковой группировки, исследования конфигураций, объяснения разрывов связи и
выбора устойчивого проекта.

## Порядок чтения перед любой работой

1. `docs/00_INDEX.md` — карта и порядок чтения по твоей роли.
2. `docs/01_SPEC.md` — норматив кейса. Приоритет над всем остальным.
3. `docs/02_DECISIONS.md` — принятые решения. Не оспаривать молча; предлагать новый ADR.
4. `docs/03_GLOSSARY.md` — имена, enum, коды ошибок. Использовать буквально.
5. Далее по роли: `04_CORE.md`, `05_API.md`, `06_STORAGE.md`, `07_UI.md`, `08_PLAN.md`,
   `10_FIXTURES.md`.
6. Официальные PDF, четыре JSON-сценария и `Расчетный модуль/geometry.py`.

## Правила

1. `01_SPEC.md` имеет приоритет над любым другим документом. При противоречии остановись и
   укажи его.
2. Расчётное ядро `core/orbita_core` не импортирует FastAPI, ORM, Redis, MinIO, фронтенд.
3. HTTP-слой вызывает application services и не содержит расчётов. React не считает метрики.
4. Никаких hardcoded идентификаторов из сценариев кейса и числа 48 в универсальной логике.
5. Каждый Run несёт `config_hash`, `engine_version`, `routing_policy`.
6. Обязательный расчёт работает при недоступных Redis, Memgraph, MinIO через локальные
   адаптеры; внешние хранилища только через адаптеры.
7. Не хранить 720 JSON-снимков на точку sweep; трасса — bitset (ADR-010).
8. Рекомендации, причины и объяснения только из метрик; LLM в v1 отсутствует (ADR-012).
9. Изменение схемы данных сопровождается миграцией и правкой `05_API.md`/`06_STORAGE.md`.
10. Функция не готова без тестов, обновлённого документа и записи в OpenAPI.
11. Экраны и стиль из `07_UI.md` не менять без указания пользователя; данные на экраны
    только из API.
12. Коммиты на русском в формате conventional commits, один коммит на логический шаг;
    комментарии в коде на русском и объясняют «почему» (ADR-016). Идентификаторы и имена
    полей на английском.
13. Не удалять пользовательские изменения. Малые проверяемые шаги. После каждого среза
    прогоняй тесты и линтеры.
14. Если нужно продуктовое решение, которого нет в ADR, не додумывай: сформулируй варианты
    и trade-offs и остановись.

## Стек

`08_PLAN.md` §3. Кратко: Python 3.12 + NumPy в ядре; FastAPI + Pydantic v2 + SQLAlchemy +
Alembic; arq на Redis; PostgreSQL 16; Memgraph + MAGE по Bolt; MinIO; React 18 + TypeScript
strict + Vite + Tailwind + ECharts + Canvas 2D; Docker Compose; pytest + hypothesis, ruff,
mypy --strict, eslint, tsc, Playwright.

## Первая итерация

Вертикальный срез до конца, без мокапов всех экранов:

```text
upload JSON → validation с JSON path → Project/Variant → Run в воркере
→ 720 графов → маршруты всех клиентов → причины → метрики
→ API → один настоящий экран «Сеть» → export cosmo-A-result-1.0
```

Задачи по порядку:

1. Аудит репозитория и gap analysis относительно `docs/`.
2. Структура репозитория по `08_PLAN.md` §2, compose со всеми сервисами и `/api/health`.
3. `orbita_core` с тестами по `10_FIXTURES.md`; golden-значения должны сойтись.
4. Независимая сверка достижимости Union-Find.
5. Project/Variant/Run API, воркер, прогресс, экспорт.
6. Экран «Сеть» на реальных данных.
7. Только после прохождения полного цикла: Outage Detective, затем Design Space Explorer.

## Формат ответа агента на задачу

Сначала краткий план и список затрагиваемых файлов. Затем реализация. В конце: какие
тесты добавлены, команды проверки, что не сделано и почему, текст коммита.

## Acceptance criteria первой итерации

- новый JSON того же формата не требует правки кода;
- ошибки входа содержат код и JSON path, все ошибки списком;
- 720 отсчётов, границы интервалов по `01_SPEC.md` §2.6;
- каждое ребро каждого непустого `path` существует на своём отсчёте;
- для каждого клиента есть `availability`, `visibility`, `max_gap_s`;
- причины разрывов приходят с backend с доказательствами;
- вариант сохраняется, воспроизводится, экспортируется и повторно загружается;
- фронтенд показывает loading, error, empty, success;
- `docker compose up` поднимает рабочую систему, `/api/health` зелёный;
- README содержит чистые команды запуска;
- ни одной мёртвой кнопки в демонстрационном сценарии.
