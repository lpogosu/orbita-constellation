## 3. Экономическая модель

Параметрическая, без выдуманных сумм. На слайде формулы и три сценария
(conservative / base / optimistic) с явными допущениями.

```text
Development cost = Σ(role_months × loaded_monthly_rate) + infrastructure + validation
Annual cost      = infrastructure_monthly × 12 + support_fte × rate × 12
Annual benefit   = projects_per_year × experiments_per_project × hours_saved_per_experiment
                   × engineer_hour_rate + avoided_rework_cost
Payback (мес.)   = Development cost / (Annual benefit / 12)
ROI              = (Annual benefit − Annual cost) / Annual cost
```

Роли пилота: backend/scientific engineer, frontend engineer, data/infra engineer, QA,
product/domain analyst, UX/UI на часть ставки.

Эксплуатационные статьи: compute на Run, объектное хранилище на Experiment, Postgres и
Memgraph, мониторинг и резервное копирование, поддержка ядра.

Данные, которые запрашиваются у кейсодержателя: число инженеров в типовом исследовании,
время на один вариант сегодня, число вариантов на проект, проектов в год, стоимость
поздней переработки конфигурации, требуемый срок хранения расчётов, требования к
размещению данных.

## 4. Roadmap после v1

### Этап 2. Инженерный пилот
- несколько проектов и пользователей, роли, audit log;
- Monte Carlo отказов, пакетный импорт сценариев;
- **ассистент инженера** (ADR-012): вопросы на естественном языке → вызовы API →
  ответ со ссылками на структурные данные; правки сценария фразой с подтверждением;
- интеграционный API для внешних систем.

### Этап 3. Production decision-support
- несколько шлюзов и произвольные клиенты как основной сценарий;
- пропускная способность и задержки;
- spatial pruning и распределённый расчёт для `N ≥ 500`;
- интеграция со STK/GMAT; корпоративное развёртывание; SLA, мониторинг, backup.

### Этап 4. Operational mode
- телеметрия, прогноз состояния, алерты, расчётное и фактическое состояние рядом.
Не выдавать за готовое.
