# 18. 3D-глобус: что нужно и как делать

| Статус | Обновлён | Заменяет | Агенту |
|---|---|---|---|
| Действует | 2026-09-12 | — | Расширение ADR-014: 3D как режим в том же слоте карты, 2D остаётся по умолчанию. Данные только из API |

## 1. Что получится

В слоте карты экранов «Сеть» и «Отказы» появляется переключатель «2D / 3D». В 3D —
вращаемый глобус в стиле иллюстраций сайта (тёмный северный космос, сияние, стеклянные
поверхности): орбитальные плоскости дугами, спутники с подписями (активные и отказавшие
разными маркерами), клиенты и шлюз на поверхности, контакты, выбранный маршрут, резервный
маршрут, подсветка компонент при разрыве. Вращение мышью, зум колесом, кнопка «Север»
возвращает камеру над полюсом. Таймлайн, выбор клиента, слои и отсчёт общие с 2D: смена
режима не меняет состояние экрана.

## 2. Что уже есть и что нужно добавить

| Есть | Нужно |
|---|---|
| Координаты спутников `x_km, y_km, z_km` в земной системе на любом отсчёте: `GET /api/runs/{id}/snapshot?t_s=` и `POST /api/preview` | ничего: это готовые декартовы координаты для сцены, масштаб 1 единица = 1000 км |
| Рёбра `edges[]` с типом `isl`/`ground` и длиной; маршруты клиентов `clients[].path`; резервные пути `backup-paths` | ничего |
| Наземные пункты: широта и долгота из сценария | перевод в декартовы координаты на сфере радиуса 6371 км (три строки) |
| Таймлайн, выбор клиента, слои, состояние stale — общие для карты | вынести их из компонента 2D-карты в общее состояние экрана, если ещё не вынесены |
| Плоскости: у каждого спутника `plane_id`; RAAN и наклонение в сценарии | дуга плоскости: окружность радиуса `R + altitude_km`, повёрнутая на наклонение и RAAN (те же формулы кейса) |
| Стиль: токены, иллюстрация Земли в полярной проекции для 2D | текстура Земли 2:1 (equirectangular) в том же стиле, 4096×2048; опционально слой ночных огней и облаков |

Новых endpoint не нужно.

## 3. Стек

- `three`, `@react-three/fiber`, `@react-three/drei` — уже совместимы с React 18 и Vite;
  drei даёт `OrbitControls`, `Html`/`Text` для подписей, `Line` (толстые линии) и
  `Instances` для сотен спутников одной отрисовкой.
- Сфера Земли: `sphereGeometry` + `MeshStandardMaterial` с текстурой; поверх — вторая
  сфера чуть больше с шейдером свечения атмосферы (Fresnel) в цвете `Orbit blue`/`Link
  cyan` из токенов, чтобы совпало с 2D-иллюстрацией.
- Спутники: `InstancedMesh` (одна геометрия, до тысяч экземпляров), цвет по плоскости, у
  отказавших другой маркер; подписи через `Html` с отсечением за горизонтом (`occlude`).
- Контакты и маршруты: `Line` из drei (`Line2`), обновляются каждый отсчёт; маршрут
  толще и цвета `Primary violet`, резервный пунктиром, ISL `Link cyan`, наземные линии
  тоньше.
- Плоскости: `Line` по 128 точкам окружности.
- Камера: `OrbitControls` с ограничением зума, автоориентация над полюсом при входе,
  `enableDamping`. Кнопки «Север» и «Сброс».
- Производительность: цель 60 кадров при 48 аппаратах и 30 при 500; перерисовка
  геометрии линий только при смене отсчёта, не каждый кадр; `frameloop="demand"`, когда
  нет воспроизведения.
- Ленивая загрузка: 3D-модуль подключается `React.lazy`, чтобы не утяжелять 2D.

Не использовать: `three-globe`/`r3f-globe` (заточены под гео-визуализацию на поверхности,
орбиты и маршруты через них неудобны), Cesium (тяжёлый и другой стиль).

## 4. Текстура в стиле сайта

Нужен файл `web/public/assets/earth-equirect.webp` 4096×2048 (соотношение строго 2:1,
бесшовный по левому и правому краю, полюса без искажений в виде «звезды»). Варианты:

1. Нарисовать в стиле иллюстраций макетов дизайн-командой на основе свободной карты
   (Natural Earth или текстуры Solar System Scope, CC BY 4.0) с цветокоррекцией под
   палитру: тёмно-синие океаны, приглушённая суша, лёгкие облака.
2. Сгенерировать изображением-моделью по промпту из §7 и проверить швы: левый и правый
   край должны совпадать (быстрая проверка — сдвинуть картинку по горизонтали на половину
   ширины и посмотреть стык), полюса — ровные.

Дополнительно, по желанию: `earth-night.webp` (огни городов) и `clouds.webp`
(альфа-канал), оба 2:1.

## 5. Как встроить

1. Компонент `web/src/globe/Globe3D.tsx` с тем же интерфейсом входных данных, что у
   2D-карты: snapshot, выбранный клиент, слои, резервный путь, компоненты, колбэки
   выбора и контекстного меню.
2. Переключатель «2D / 3D» в углу слота карты, состояние в `localStorage`.
3. Общие подписи, легенда и контекстное меню спутника («Задать отказ», «Показать
   критичность») работают в обоих режимах.
4. Экран «Отказы» в режиме «Рядом» — два глобуса с синхронной камерой.

## 7. Промпт для генерации текстуры

Соотношение 2:1, 4096×2048, equirectangular, бесшовно по горизонтали. Стиль — как
иллюстрации сайта: тёмный северный космос, глубокие синие океаны с лёгким свечением у
берегов, приглушённая суша холодных оттенков, тонкие облака, без текста, без сетки, без
рамок, полюса ровные без радиальных артефактов. Отдельно (по желанию) ночной слой: чёрный
фон, тёплые огни городов по реальному распределению, 2:1.

Проверка после генерации: сдвинуть изображение по горизонтали на половину ширины —
стык не должен быть виден; полюса — однородные полосы без «звезды»; Гренландия и
Антарктида на своих местах, иначе спутники над Мурманском окажутся не над Мурманском.

## 8. Оценка

Одна карточка агента: 1–2 часа работы, зависимостей три пакета, новых endpoint нет.
Риск один — стиль текстуры: если генерация даст «фотореализм», глобус выпадет из дизайна;
поэтому текстуру утверждает владелец до запуска карточки.
