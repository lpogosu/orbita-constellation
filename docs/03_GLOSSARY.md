## 1. Термины кейса

| Термин | Поле / имя в коде | Определение |
|---|---|---|
| Спутниковая группировка | `constellation` | Совокупность спутников; в кейсе 48 аппаратов, три очереди по 16 |
| Орбитальная плоскость | `plane`, `plane_id` | Плоскость движения группы спутников; в кейсе три |
| RAAN | `raan_deg` | Прямое восхождение восходящего узла: ориентация плоскости, [0; 360) |
| Фазирование | `phase_deg` | Общий сдвиг спутников плоскости вдоль орбиты, [0; 360) |
| Слот | `slot_deg` | Начальное угловое положение спутника в плоскости; к нему прибавляется `phase_deg` |
| Очередь запуска | `launch_batch` | Этап, на котором спутник выводится: 1, 2 или 3 |
| Этап развёртывания | `launch_stage` | Сколько очередей запущено: 1 → ≤16, 2 → ≤32, 3 → 48 |
| Клиентский пункт | `client`, `client_id` | Наземная точка, для которой проверяется путь до шлюза. Не ретранслирует |
| Шлюз | `gateway`, `gateway_id` | Наземная станция, конец маршрута, выход в наземную сеть |
| Угол возвышения | `elevation_deg` | Угол спутника над горизонтом пункта; контакт при `≥ min_elevation_deg` |
| ISL | `isl`, `isl_range_km` | Межспутниковая линия; доступна при расстоянии `< isl_range_km` и без пересечения Земли |
| Геометрическая видимость | `visibility` | Хотя бы один активный спутник виден пункту. Не гарантирует путь |
| Сквозная достижимость / доступность | `availability` | Существует путь клиент → спутники → шлюз в текущем отсчёте |
| Маршрут | `path` | Последовательность идентификаторов от клиента до шлюза |
| Переход | `hop` | Одно ребро маршрута; число переходов включает две наземные линии |
| Перерыв связи | `outage` | Непрерывная последовательность отсчётов без пути |
| Максимальный перерыв | `max_gap_s` | Самый длинный перерыв за горизонт, в секундах |
| Отсчёт / шаг расчёта | `tick`, `t_s`, `step_s` | Дискретный момент сетки; `t_s` в секундах от начала |
| Горизонт | `horizon_s` | Продолжительность расчёта, секунды |
| Активный спутник | `active` | `launch_batch ≤ launch_stage` и нет действующего отказа |
| Отказ спутника | `failure` | Интервал `[start_s; end_s)` недоступности аппарата |
| Недоступность шлюза | `gateway_outage` | Интервал `[start_s; end_s)` недоступности шлюза |

## 2. Проектные термины

| Термин | Имя в коде | Определение |
|---|---|---|
| Проект | `Project` | Контейнер инженерного исследования: варианты, запуски, эксперименты |
| Вариант | `Variant` | Неизменяемая версия сценария `cosmo-A-1.0` с `parent_variant_id` и diff параметров |
| Запуск | `Run` | Выполнение расчёта конкретного варианта конкретной версией ядра и политикой маршрутизации |
| Снимок | `Snapshot` | Состояние сети на одном отсчёте: спутники, рёбра, маршруты клиентов, причины |
| Трасса | `trace` | Contact plan запуска: узлы, возможные рёбра, битовая матрица `отсчёты × рёбра` |
| Contact plan | `contact_plan` | Список интервалов существования каждого контакта; то же, что трасса, в интервальном виде |
| Эксперимент | `Experiment` | Sweep по одному или двум параметрам с бюджетом; состоит из `ExperimentPoint` |
| Точка эксперимента | `ExperimentPoint` | Одна конфигурация внутри sweep с её метриками; может быть материализована в Variant |
| Рекомендация | `Recommendation` | Детерминированный вывод из метрик по ADR-006 с дельтами |
| Evidence Pack | `evidence_pack` | Архив: effective scenario, версия ядра, метрики, перерывы, маршруты, сравнение, рекомендация |
| Experiment Lineage | `lineage` | Граф происхождения вариантов: кто из кого создан и с какой дельтой |
| Effective scenario | `effective_scenario` | Полный сценарий, который реально использован в расчёте, включая правки пользователя |
| Config hash | `config_hash` | sha256 канонического effective scenario + `routing_policy` |
| Версия ядра | `engine_version` | Семвер расчётного ядра, например `orbita-core-1.0.0` |
| Degraded mode | `degraded_mode` | Работа одиночного расчёта при недоступных Redis/Memgraph/MinIO через локальные адаптеры |

## 3. Enum

### 3.1 Причины отсутствия маршрута `OutageCause`

| Значение | Условие | Текст в интерфейсе |
|---|---|---|
| `NO_CLIENT_COVERAGE` | у клиента нет ни одного видимого активного спутника | Нет видимых спутников |
| `GATEWAY_OUTAGE` | все шлюзы в периоде недоступности | Шлюз недоступен |
| `NO_GATEWAY_COVERAGE` | доступный шлюз не видит ни одного активного спутника | Нет связи со шлюзом |
| `NETWORK_PARTITION` | клиент и шлюз видят спутники, но те в разных компонентах | Разрыв межспутниковой сети |
| `INTERNAL_INCONSISTENCY` | путь не найден, но ни одна причина не сработала | Ошибка расчёта |

Причины могут сочетаться: `causes[]` содержит все сработавшие, `primary_cause` — первую
по порядку таблицы.

### 3.2 Стратегии маршрутизации `RoutingPolicy` (ADR-003)

| Значение | Описание |
|---|---|
| `bfs_shortest` | BFS, минимум переходов, пересчёт каждый отсчёт. По умолчанию |
| `persistent` | удержание текущего маршрута, пока он валиден; при разрыве BFS |
| `dijkstra_distance` | Dijkstra, вес = длина линии в км |

### 3.3 Статусы `RunStatus` и `JobStatus`

`queued` → `running` → `succeeded` | `failed` | `cancelled`

### 3.4 Стадии выполнения `RunStage`

`validate` → `geometry` → `contacts` → `routing` → `analytics` → `persist` → `complete`

### 3.5 Роли наземных пунктов `SiteRole`

`client` | `gateway`

### 3.6 Коды ошибок API `ErrorCode`

| Код | Когда |
|---|---|
| `UNSUPPORTED_SCHEMA_VERSION` | `schema_version` не `cosmo-A-1.0` |
| `INVALID_SCENARIO_FIELD` | значение вне диапазона или неверного типа; `path` указывает поле |
| `DUPLICATE_NODE_ID` | повтор идентификатора спутника, плоскости или пункта |
| `UNRESOLVED_REFERENCE` | ссылка на несуществующую плоскость, спутник или шлюз |
| `INVALID_TIME_GRID` | `horizon_s`/`step_s` не целые, не положительные или не кратные |
| `INVALID_OUTAGE_INTERVAL` | интервал вне горизонта или `start_s ≥ end_s` |
| `MISSING_SITE_ROLE` | нет клиента или нет шлюза |
| `RUN_NOT_READY` | запрошен результат незавершённого Run |
| `RUN_FAILED` | Run завершился ошибкой; `details` содержит стадию |
| `EXPERIMENT_BUDGET_EXCEEDED` | sweep превышает лимит точек или времени |
| `INTERNAL_INCONSISTENCY` | расхождение BFS и Union-Find или причина не определена |
| `STORAGE_UNAVAILABLE` | внешнее хранилище недоступно и degraded mode не разрешён |
| `NOT_FOUND` | сущность с таким идентификатором отсутствует (HTTP 404) |

### 3.7 Флаги интервала перерыва

`truncated_by_horizon: bool` — перерыв примыкает к началу или концу горизонта (ADR-004).

### 3.8 Вид ребра снимка `EdgeKind`

| Значение | Ребро |
|---|---|
| `isl` | спутник — спутник |
| `ground` | клиент — спутник или шлюз — спутник |

## 4. Соглашения об именах

- Разделы сценария `failures` и `gateway_outages` обязательны; пустой список допустим,
  отсутствие раздела — ошибка `INVALID_SCENARIO_FIELD` с путём до раздела. Так же ведёт
  себя эталонный `geometry.py`.
- Идентификаторы сущностей: UUID v4 в API; идентификаторы из сценария (`S01`, `C65`)
  остаются строками как в файле.
- Время всегда в секундах от начала расчёта (`t_s`), в интерфейсе форматируется как
  `ЧЧ:ММ`.
- Доли в API в диапазоне [0; 1]; проценты только в интерфейсе.
- Расстояния в километрах с суффиксом `_km`, углы в градусах с `_deg`, время в секундах
  с `_s`.
- Метрики конфигурации: `min_client_availability`, `mean_client_availability`,
  `worst_max_gap_s`, `mean_hops`, `max_hops`, `route_switches_total`,
  `backup_path_count_min`, `outage_count_by_cause`. Агрегат по конфигурации получает
  суффикс способа свёртки (`_total`, `_min`), метрика клиента остаётся без суффикса
  (`route_switches`, `backup_path_count`).
